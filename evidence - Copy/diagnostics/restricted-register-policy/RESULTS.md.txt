## Exact addition target

The consolidated source checked this public theorem without a model-correspondence premise:

```lean
theorem PastaBridge.AdditionCorrectness.addition_correct
    (field : PastaCurves.PastaField)
    (binding : PastaBridge.AdditionCorrectness.Binding) (state : MachineData)
    (admissible : PastaBridge.AdditionMachine.Admissible binding)
    (inputs : PastaBridge.AdditionCorrectness.InputContract field binding state) :
    ∃ after : MachineData,
      PastaBridge.AdditionMachine.runWithBinding binding state = .ok after ∧
      PastaBridge.AdditionCorrectness.Postcondition field binding state after
```

`InputContract` requires the three supplied modulus words to equal the field's
modulus and both four-word inputs to represent integers below that modulus.
Every word is intrinsically below `2^64` because Kraken stores `UInt64`.
`Admissible` permits the fixed Rust register class and requires separation only
for written operands. Equal-valued read-only inputs may share registers.
Incoming flags, scratch words, memory and SP are unrestricted.

`Postcondition` states exact equality with `AArch64.addMod`, bounded output,
output below the modulus, congruence to the input sum, unchanged memory/SP,
unchanged registers outside the written allocation, unchanged read-only
operands and X19/X29, plus the retained-template/allocated-program equality and
checked operand metadata. The full structure definitions and statement are in
`proofs/AdditionCorrectness.lean`; `proofs/Audit.lean` checks the exact public
type and prints those structures. The field parameter covers both `pallasBase`
(Fp) and `vestaBase` (Fq). The theorem's axiom census is `propext`,
`Classical.choice`, `Quot.sound`.

## Exact arithmetic model endpoints

The following reused model theorems supply the final arithmetic specifications. Addition's assembly-to-model correspondence is checked separately and composed with this specification. The declarations and helper inventory are also retained in `proofs/THEOREMS.md`.

```lean
theorem PastaAssemblyBridge.Arithmetic.addition
    (F : PastaField) (lhs rhs : Limbs)
    (hlhs : lhs.Bounded) (hrhs : rhs.Bounded)
    (hlhs_lt : lhs.toNat < F.modulus.toNat)
    (hrhs_lt : rhs.toNat < F.modulus.toNat) :
    let res := addMod lhs rhs F.modulus
    res.Bounded ∧ res.toNat < F.modulus.toNat ∧
      res.toNat ≡ lhs.toNat + rhs.toNat [MOD F.modulus.toNat]
```

```lean
theorem PastaAssemblyBridge.Arithmetic.multiplication
    (F : PastaField) (lhs rhs : Limbs)
    (hlhs : lhs.Bounded) (hrhs : rhs.Bounded)
    (hcontract : mulContract lhs rhs F.modulus = true) :
    let res := mulMont lhs rhs F.modulus F.inv
    res.Bounded ∧ res.toNat < F.modulus.toNat ∧
      2^256 * res.toNat ≡ lhs.toNat * rhs.toNat [MOD F.modulus.toNat]
```

`Limbs.Bounded` means all four limbs are below `2^64`. Addition requires both represented integers below the field modulus. Multiplication requires the exact upstream `mulContract`: `lhs.toNat < p`, or `rhs.toNat < p` and each of `rhs.l1 + 3`, `rhs.l2 + 3`, `rhs.l3 + 3` is at most `2^64`. Both operands must be bounded in either branch. These generic `PastaField` statements apply to both `pallasBase` (Fp) and `vestaBase` (Fq); the retained constants, Montgomery inverse and primality proofs supply those instances.

The arithmetic endpoints' axiom census is exactly `propext`, `Classical.choice`, `Quot.sound`. The seven word lemmas use at most `propext` and `Quot.sound`; the register helpers use at most `propext`. No new correctness axiom is introduced. These successful endpoints contain no `sorryAx`. Failed experimental proofs are not target theorems.

## Executable and negative checks

This MIR evaluator is test infrastructure, not a proved Rust wrapper translation.

For each field, all 49 pairs from seven boundary inputs are run with all 16 incoming NZCV patterns and two register allocations. Another 32 runs share equal-valued read-only inputs. This totals 3,168 runs over three allocations. Scratch and other registers, SP and a nonempty memory sentinel are initialized before execution. All sampled outputs and memory/SP/protected-register frame checks pass. These finite checks do not prove arbitrary flags, scratch, bindings or frame states.

Two supported but semantically broken programs are automatically derived from the real extraction and executed. Changing carry propagation from `adcs` to `adds` causes 32 mismatches. Swapping an operand binding also causes 32 mismatches. For `lhs = 18446744073709551615`, `rhs = 1`, all initial flags false, the correct answer is `18446744073709551616`; the broken carry gives `0`, and the wrong binding gives `36893488147419103231`. Thus these negatives fail on semantics, not merely on hashes.

Multiplication has 4,000 passing positive executions across both fields, all
16 NZCV patterns and three allocations, including equal read-only aliases.
Vectors cover both branches of the exact upstream `mulContract`, including a
fully unreduced 256-bit operand and the other operand's upper-limb headroom

The checked whole-program memory statement is exactly:

```lean
theorem PastaBridge.AdditionMachine.binding_memory_frame
    (binding : Binding) (state : MachineData) :
    (runWithBinding binding state).map MachineData.dmem = .ok state.dmem
```

It quantifies over every `Fin 15 → XReg` binding and every initial state, with no assumptions on flags, scratch or memory. Register separation is unnecessary for this memory claim. The complete-program stack frame likewise imposes no binding or initial-state assumptions. The complete-program register frame requires only that the queried physical register differ from every written operand's register; an admissible Rust allocation therefore preserves X19 and X29. The read-only-register frame assumes separation of written operands and allows read-only aliases.

The complete-program allocation theorem is exactly:

```lean
theorem PastaBridge.AdditionLift.all_bindings_simulation (binding : Binding)
    (separated : KrakenBinding.Separated AdditionStep.written binding)
    (state : MachineData) :
    AdditionStep.LiftedRel binding AdditionMachine.canonicalBinding
      (AdditionMachine.runWithBinding binding state)
      (run retainedAdditionProgram (canonicalState binding state))
```

`Separated` requires every written operand's register to differ from every other operand's register. Read-only inputs can share registers, and such inputs necessarily have equal initial values. `canonicalState` copies the fifteen operand values into canonical registers while retaining incoming flags. `LiftedRel` requires both executions to succeed and agree on every corresponding operand register and all NZCV flags. This includes arbitrary scratch contents and initial flags; no arithmetic input bounds are needed for allocation correspondence. The decoder and encoder traverse the actual retained AST, and their closed certificates link that program to the singleton sequence used in the inductive proof. Exact frame statements, the instantiation certificate and the checked write-mask link are in `proofs/THEOREMS.md`. All these declarations use only standard Lean axioms, without `sorryAx` or new correctness axioms.
